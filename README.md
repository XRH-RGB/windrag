# 风知 · 风电智能运维与数据分析平台

在现有 WindRAG 项目上增加风电数据与运维功能。真实系统使用原生 HTML / CSS / JavaScript、Python 标准库、SQLite；图表为根据接口数据绘制的 SVG。保留原有 FAQ、知识检索、知识版本、BERT 接入和可选生成模型功能。

## 启动

1. 完整解压压缩包，进入“风知_WindRAG系统”文件夹。
2. 安装 Python 3.10 或更高版本，安装时勾选加入 PATH。基础系统无需 pip 安装依赖。
3. 双击“启动系统.cmd”或“start.bat”。
4. 后台服务检查就绪后，浏览器自动打开独立登录页。启动窗口可以关闭；电脑重启后需再次双击启动文件。启动日志在 data/service.log。

命令行也可以运行：

```powershell
python launcher.py
```

后台启动优先使用 http://127.0.0.1:8770/ ，API 地址为同一地址下的 /api/。前后端由同一进程提供，不需要分别启动。启动入口带 ?login=1，优先显示登录界面。端口冲突时自动选择空闲端口，重复启动复用同一版本、同一数据库的服务，实际地址以启动窗口为准。需要前台调试及指定端口可运行 python launcher.py --port 8877，此调试方式需保持窗口打开。

不能通过双击 web/index.html 使用业务系统；它需要后端。免登录汇报文件 web/presentation.html 和压缩包根目录的“风知_风电智能运维与数据分析平台_项目汇报.html”可直接双击打开。原有“风知_WindRAG_交互演示.html”保留知识问答和身份切换，不连接真实业务数据库。

## 固定演示数据与实际计算

首次运行生成两个风场、十台 3000 kW 风机、七天逐小时观测（1680 条）、告警、巡检、故障、维修与基线预测结果。随机种子固定，日期以首次初始化日为基准。设备状态是最近历史观测快照，不连接实时 SCADA；刷新重新读取数据库，不随意生成新的随机读数。

CSV 示例位于 demo_wind_data.csv。系统“数据导入与处理”还可下载按当天生成的 Demo CSV，适合演示今天的图表。

导入流程：
- 浏览器读取 CSV，后端检查扩展名、必需列、风机权限和行数（1–5000 行）。
- 显示实际行数、字段质量统计与预览，确认后将原始批次保存到 SQLite。
- 执行清洗：重复时间保留末行、数值缺失/非数值填列均值、超出物理范围截断、无效时间剔除、时间排序。
- 保存清洗结果、前后质量报告和预览；同一风机同一时间的已确认观测会被导入结果替换，防止重复统计，原始批次仍保留。
- 清洗后的数据供查询、分析、预测和检测使用。CSV 的 time 应为不带时区的 ISO 时间。

数值质量范围：风速 0–40 m/s、功率 0–6000 kW、温度 -40–120 ℃、转速 0–30 rpm。异常预警阈值与质量范围不同：默认温度 >80 ℃、转速 >22 rpm、风速 >25 m/s 或功率超过风机额定值产生告警。管理员可在系统设置修改前三项。重复检测按“风机、时间、指标”去重。

统计输出有效数据量、均值、最小值、最大值和总体标准差。发电量按同一风机相邻观测进行梯形积分，间隔超过 6 小时不估算；区间第一个观测之前及最后一个之后不外推，单位 kWh。

预测使用“持续性时间序列基线”：上一时刻实际功率预测下一时刻，最后 20% 时间段用于回测；未来各步保持最后观测功率。输出 MAE、RMSE、R²、历史值、回测值和未来值。R² 在实际值无波动时为空，不能把基线结果当作生产预测精度。至少 12 条有效观测，预测 1–72 步，步长取历史正时间间隔中位数。

## 现场演示

admin 登录 → 驾驶舱 → 风场/风机详情 → 下载 Demo CSV → 上传预览 → 确认导入 → 执行清洗 → 数据查询 → 运行分析 → 功率预测 → 异常检测 → 处理告警 → 新增维修记录 → 报表生成与 CSV 导出 → 操作日志 → 退出。

再用 operator 登录验证运维操作与风场范围；用 user 登录验证只读页面和预测结果查看。

汇报 HTML 为九章：封面、背景、架构、整体流程、系统功能、实际演示、成员分工、成果、结束页。支持目录、键盘翻页、全屏、流程节点点击、逐步讲解、九位成员自动轮播和免登录数据计算实验。系统地址默认 8765，端口不同可在汇报“实际演示”章节修改。讲解实验的数据只在当前页面内存中计算，真实持久化操作通过“打开系统”进行。

## 原有 RAG 与流程对应

在线采用上传流程图的 Stage 0–7 组织：查询上下文 → 快速路由 → 检索准备 → FAQ 阈值匹配 → 文档检索排序 → 证据准备 → 答案组织与引用检查 → 归档反馈。
- 问候、致谢、告别、越界、实时数据和设备控制请求有直接响应分支。
- 原问题精确 FAQ 命中跳过 BERT 与文档检索。FAQ 来源需有效、已发布、授权，且与审核内容一致。
- 非精确问题按配置调用真实 BERT 服务，无模型时使用规则；不显示虚构模型概率。
- 检索使用实际 BM25 及可选向量融合。得分是匹配相关度，不是准确率。
- 当前传输是 HTTP，存储为 SQLite；未冒充参考图中的 WebSocket、Milvus、BGE CrossEncoder、MySQL。
- 离线知识流程：资料接入 → 候选版本 → 标准化与切分 → 索引准备 → 质量核对 → 审核发布或继续修订 → 历史追溯与回滚。
- 生成模型未配置时返回可追溯原文摘录；配置后进行生成与引用编号检查。知识内的文字不会作为系统指令。

可选模型设置见 .env.example、BERT接入说明.md 和 bert_service.py。无训练模型时不需要安装 requirements-bert.txt。现有基础运行不需要外网或任何 API Key。

## 目录

- server.py：HTTP、登录会话、知识接口与静态资源
- operations.py：风场风机、CSV、数据计算、告警运维、报表、用户管理
- pipeline_core.py：规则 / BERT 路由、FAQ、实际检索评分
- launcher.py、启动系统.cmd、start.bat：本地启动与端口处理
- web/index.html、app.js、ops.js、style.css、ops.css：业务界面
- web/presentation.html：独立免登录汇报
- web/demo.js、demo_engine.js：原有知识交互演示
- seed.json、faq.json：示例知识和标准 FAQ
- demo_wind_data.csv：导入示例
- tests/：接口、权限、完整业务链路、启动复用、RAG 演示测试
- data/windrag.db：首次运行生成的 SQLite 数据库（不打包）
- data/last_port.txt：最近运行端口

可通过 WINDRAG_DATA 环境变量更改数据库目录。运行前如需备份，请关闭服务后复制 data 文件夹。压缩包不会包含本机运行数据库、私有 .env 或模型权重。

## 接口

身份与知识：/api/login、/api/me、/api/logout、/api/password、/api/docs、/api/chat、/api/ingest、/api/publish、/api/history、/api/settings。
业务：/api/ops/meta、dashboard、farms、turbines、data、import/preview、import/confirm、data/clean、analysis、prediction、monitoring、detect、alerts、maintenance、reports、users、logs、parameters、profile。
GET 查询，POST 执行写入/计算操作，JSON 请求。写接口要求 X-WindRAG: 1，并验证 Origin。响应使用 JSON；错误包含 error 说明及 400/401/403/404/409 状态。服务仅绑定 127.0.0.1，拒绝未知 Host。
